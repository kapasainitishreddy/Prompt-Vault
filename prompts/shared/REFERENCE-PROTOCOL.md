# REFERENCE PROTOCOL · research taste without cloning

When given a design gallery, UI reel, competitor site or screenshot, do **not** produce a lookalike. Extract portable principles and form an **original** product-specific design.

## Step 1 · Collect diverse inspiration
Choose up to three references from **different visual families**. Example:
- Reference A: composition and story from a Kombai design.
- Reference B: state feedback from Bencho.
- Reference C: a typographic/editorial source unrelated to the product's competitors.

Record URL, observation date, rights status, the specific pattern being studied, and why it serves the user job. If a page fails to load, say unverified.

## Step 2 · Analysis without appropriation

For each reference write:
- Hierarchy: what draws attention first and why?
- Composition: asymmetry, grid, size contrast, rhythm and density.
- Typography: role, scale, measure, weight and fallbacks (not same branded font by default).
- Motion: trigger, state transition, fallback, interruption, and why it helps.
- Accessibility: affordances, targets, semantics and likely risks.
- **Avoid copying:** logo, layout proportions as a whole, distinctive assets, text, exact colors, logos, characters, screenshots, trademark-bearing look.

## Step 3 · Originality brief

Create three *materially different* designs, each mixing the references only at the level of abstract principles. Use real copy, states and imagery. Each direction needs a structural twist born from the product's domain: scheduling → time, music → waveform, publishing → book craft, developer tools → inspectable code, analytics → legible comparisons.

Perform the logo-swap test and content-truth audit. Reject both easy lookalikes and unrelated visual gimmicks.

## Step 4 · Rights decisions

- **Permissive source:** MIT/Apache/etc **plus** asset/dependency review; preserve required notices.
- **Use-in-app but redistribution restricted:** canvas UI (Commons Clause) or Originkit catalog (specific terms); only downstream under terms, **not bundled in our MIT prompt/component collection**.
- **Reference-only/unknown rights:** gallery screenshots, brand skins, studio art. Link and analyze, never bundle.
- **Unverified live link:** GitHub repo or documentation only, clearly state what's unknown.

See [source rights](../../research/supplied-resources.md).

## Step 5 · Ship and critique

Actually implement using local files, test at real viewports/devices, capture the result if possible, review against [anti-slop protocol](ANTI-SLOP-AUDIT.md), and iterate a maximum four rounds. Provide source attribution only where needed; do not confuse conceptual inspiration with copying source.
